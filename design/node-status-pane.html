One node pane, three states

A single dock pane listing every node in the graph and what each one is doing. It replaces two planned panes, a node outliner and a build list, with one view. Rows never reorder: the left half of a row is identical in every state, and only the trailing slot changes. Fake data, real palette, real typeface, real node names.

Settled

Six structural decisions, then a visual pass over the detail. All of it is drawn above.

  1. One pane, not two. Rows never reorder, and a row's left half is identical in every state. Only the trailing slot changes, so nothing moves under you when a build starts.
  2. Canvas and pane both, at different fidelity. Node headers keep the dot alone; the pane carries glyph, word and detail.
  3. Outputs stays the source of truth for build inclusion. The pane's build chip mirrors it, on the same two-controls-one-value pattern as the viewport's output picker.
  4. Dependency order always, with an explicit user sort for canvas order, alphabetical, or stale first. Sorting is a choice you make, never one the state makes for you.
  5. Large graphs get collapsible subgraph groups, a filter field with quick chips, and a compact one-line density.
  6. Elapsed time only, plus a percentage for the nodes that report one. No build-level estimate, because it would be extrapolation and wrong exactly when it matters.
  7. Names disambiguate on collision only. A dimmed type suffix appears on the colliding rows alone, computed over the rows currently visible. Two nodes of the same type and name take a trailing ordinal in canvas order, since a type suffix cannot separate them.
  8. A collapsed group reports its worst state, as pip and stripe, with the count in that state and then the total. Precedence is failed, stale, active, not evaluated, current. An all-current group shows the total alone, so a phrase appearing is itself the signal.
  9. The pin leaves the trailing slot for the glyph cell, since it is an identity flag rather than a status, and the slot caps at two marks: a status word first, then the single highest-fidelity view chip, with the dashed build mirror suppressed when the word already speaks to the build. Because the pin displaces the glyph, a pinned row always spells its state out in the trailing slot, as a word, or as the progress bar and its number when it is building. No row is ever left resting on stripe colour alone.
  10. Sort persists with the project; the filter does not. A filter is a momentary question, and restoring one means opening to a list that hides most of the graph with no memory of why. While a filter is active the summary states the hidden count and offers a way out.
  11. Reduced motion keeps the meaning. The indeterminate hatch fills the whole track and stops moving, and the elapsed time brightens to carry more of the signal. Determinate bars are untouched, because they move only when the value moves.
  12. The pane gets the third rail icon, after World and the Subgraph Library, using the same list mark as its title.

What this costs to build

Most of the pane needs no engine work. Only the live build picture does: one observational seam, plus opt-in reporting from the slow operators.

Idle and after-build available today

Graph::cache_status already returns current-versus-stale for every node in a pull without evaluating anything. Bypass, pinning, wiring and build inclusion are readable from the graph. Build availability is the field-store lookup the viewport's source toggle already does.

Queued, active, done engine seam

The evaluator computes nodes one at a time in dependency order and emits nothing. It needs an optional progress sink, notified as each node starts and finishes. Purely observational, so determinism is untouched.

Percentage within a node operators opt in

A bar inside a node means the operator reports fractional progress, such as erosion's iteration i / N. Nodes that do not report show elapsed time, never an invented percentage.

Where the small pieces live plumbing

The rail icon is one DockPane registration at order 20. The saved sort is a ViewState field with a serde default, the additive pattern frames and camera used. Reduced motion has no query through egui, so it reads an application preference.

Mockup only: no engine data, no live state. Palette and typefaces are the application's own, taken from crates/ymir-gui/src/theme.rs and assets/fonts, so the panel reads at the fidelity of the real chrome. The surrounding page follows your light or dark preference; the panel does not, because the application is dark chrome only.
