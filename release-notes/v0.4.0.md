Ymir is a node-based procedural terrain generator. You build terrain by wiring nodes together,
watch it in a 3D viewport, and export heightmaps for a game engine or a DCC package.

**Ymir runs on Windows.** This release adds a Windows build alongside the Linux one, tested on
real hardware and checked on every change by CI.

## Windows

Download `ymir-windows-x86_64.zip` below, unzip it anywhere, and run `ymir-gui.exe`.

The binaries are unsigned, so SmartScreen warns the first time you run one. Choose **More info**
and then **Run anyway**. The warning says the file carries no code-signing certificate, which is
true; it is not a report of anything found in the file.

Ymir keeps its settings in `%APPDATA%\Ymir` and its build cache in `%LOCALAPPDATA%\Ymir`.
Deleting either is safe: the cache only costs rebuild time.

You need a GPU with working Vulkan or DX12 drivers. The editor will not start without one.

## What that took

Less than it sounds. The engine compiled for Windows already, and nothing in it reached for a
Unix-only interface. What was missing was where files go: Ymir knew only the Linux convention, so
on Windows the preferences, recent projects, default startup graph, subgraph library, session log
and build cache all had nowhere to live and silently did nothing. Each now goes to the right place
on each platform, and Linux paths are unchanged, so an existing installation keeps its settings.

The editor also no longer opens a console window behind itself on Windows.

## Also in this release

- The command line reference and the install guide cover Windows.
- The session log now records which GPU adapter and backend a build ran on, which is the first
  thing worth knowing about a slow or wrong result on any platform.

## Requirements

- Linux on Wayland or X11, or Windows 10 or later, on x86_64.
- A GPU with working drivers: Vulkan on Linux, and Vulkan or DX12 on Windows. The 3D viewport
  runs through wgpu, and the editor will not start without one.

## Install

**Windows**: unzip `ymir-windows-x86_64.zip` and run `ymir-gui.exe`. A readme inside covers the
SmartScreen warning.

**Linux**: download `ymir-gui-linux-x86_64`, make it executable, and run it:

```
chmod +x ymir-gui-linux-x86_64
./ymir-gui-linux-x86_64
```

`SHA256SUMS` covers every asset if you want to verify a download. `ymir-cli` is the headless
runner, which builds a saved project from the command line.

Building from source is described in the
[install guide](https://liminalfield.github.io/ymir/install/).

## Upgrading from 0.2

Project files changed shape in 0.3 and a version 2 file does not open in 0.2 or earlier. If you
are coming from 0.2 directly, its projects will not open here either; see the
[0.3.0 notes](https://github.com/liminalfield/ymir/releases/tag/v0.3.0) for what changed and why.
Projects saved by 0.3 open in this release unchanged.

## Known limits

- **x86_64 only**, on both platforms. There are no ARM builds, and no macOS build: an unsigned
  macOS application will not open without a Gatekeeper override, and notarization needs a paid
  Apple developer enrolment.
- **The Windows binaries are unsigned**, so SmartScreen warns on first run. A code-signing
  certificate is a recurring cost that Ymir does not carry yet.
- **No installer.** Windows gets a zip, not an MSI, and Ymir is not on winget.
- **A preview is not a build.** Erosion is an iterative simulation, so it is resolution-dependent:
  a preview is representative of a build rather than identical to it. The build is the source of
  truth.
- **The save format is not stable yet.** Ymir is in `0.x` and makes no compatibility promise until
  1.0.
- **There is no tutorial yet.** The reference is complete, with a page per node, and a
  start-to-finish walkthrough is still to be written.
